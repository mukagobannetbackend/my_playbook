# TradeVault delivery outcomes

- [x] **Responsive fast capture and journal management** — Help target users complete the main task quickly on a phone and a computer; support onboarding, intuitive navigation, screenshot upload/create, view, edit, and delete flows, and gentle reflection prompts. Evidence: responsive Flask pages, touch-friendly navigation, onboarding, capture and entry screens, optional reflection prompts, and owner-scoped soft-delete are implemented; account and entry flows are covered by integration tests.
- [x] **Email access and password recovery** — Let users review screenshots anywhere by logging in using an email; recover a forgotten password using the email through an expiring single-use reset link. Evidence: hashed passwords, email/password sessions, one-time hashed reset tokens, session invalidation, generic anti-enumeration responses, a setup-required notice when email delivery is missing, and password-change/recovery tests. **Deployment prerequisite:** configure a verified SMTP sender and the public `APP_BASE_URL` before email delivery can operate.
- [x] **Durable screenshot review and writing** — Let users download screenshots, write about them anywhere, and still save changes; persist screenshot records and notes so they remain available across sessions/devices. Evidence: managed MySQL schema is applied, managed storage presign access was confirmed, production storage fails closed instead of writing files to an ephemeral container, reflections persist to the database, race-safe autosave with retry is implemented, and individual/ZIP downloads are available. Local test uploads use isolated temporary storage only.
- [x] **Organized discovery and similarity review** — Provide search or useful filters; prepare screenshots according to days and how similar they are, with chronological trading-day groups and same-day near-duplicate groups. Evidence: symbol/market/note/name search, date filters, paginated archive results, and average-hash near-duplicate groups with a configurable distance threshold.
- [x] **Notifications and settings** — Include in-app notifications and settings for account and notification preferences. Evidence: notification inbox/read state, journal and security update preferences, editable display name, and password settings are implemented; changes to profile and preferences do not overwrite each other.
- [x] **Modern Flask app and deployment bundle** — Use Python, Flask, HTML and CSS with a super-modern responsive style; include deployment instructions/configuration and deliver the complete project in a ZIP archive ready for deployment. Evidence: soft-observatory-led styling, pinned Flask dependencies, Docker/Gunicorn startup, migrations, environment example, root route manifest and deployment README are included; the current WebDev project has server/database and container health settings applied; project-specific WebDev settings are documented separately because they are not embedded in the source ZIP.
